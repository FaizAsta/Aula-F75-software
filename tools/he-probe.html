AULA F75 HE probe

Asks your keyboard who it is and what it answers, then saves the answers to a text file. Read-only: it never changes anything on the keyboard.

This browser cannot talk to USB devices. Open this page in Google Chrome or Microsoft Edge on a computer (not a phone).

Before you start

  1. Close the official AULA driver (website or program) and the Aula Control app. Only one program can use the keyboard at a time.
  2. Set the keyboard to the way you want to test: USB-C cable or 2.4G dongle. On 2.4G, press a key right before step 2 so it is awake.
  3. Do the whole thing once per connection (cable, then dongle) and send both files.

Step 1: choose the keyboard

Press the button, then tick every entry that could be your keyboard: anything with AULA, F75, HE, "USB Receiver" or a name you do not recognise. Ticking extra entries is fine. Press Connect.

Step 2: run the scan

Takes about 10 to 30 seconds.

    What exactly does this send?
    
Only read requests, the same ones Aula Control already uses:

    
    
      
  • F75 HE style: 0x10 device info, 0x13 lighting, 0x14 per-key colours.
    • 
      
  • F75 / F75 Pro / F87 dongle style: 0x4a battery status.
    • 
      
  • F75 / F75 Pro / F87 cable style: a read of the lighting block (0x84) on feature report 6.
    • 
    

    
It never sends write, reset, calibration or firmware commands, and the code refuses to build them. The report holds the USB ids, the interface layout, the raw replies and your browser name. Nothing else about your computer.
